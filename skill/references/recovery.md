# Recovery and invalidation

Every Implementer, Correctness Reviewer, Tester, Security Reviewer, and Verifier run has a random generation. State and checkpoint bind role, Stage, Slice, business attempt, `base_sha`, `candidate_id`, owner/worker identities, external session, worker sequence, and checkpoint epoch. Recovery rejects any mismatch and never takes over while the recorded owner is alive.

For a stopped worker, `harness recover` accepts only the exact generation-specific output path and strict schema. It revalidates attempt and current candidate before copying evidence into the trusted control plane. Missing, stale, or invalid handoffs enter `BLOCKED`. A handoff found after a terminal block is reported but does not jump the checkpoint.

A new Implementer attempt invalidates all prior implementation, gates, assessor, Verifier, and checkpoint evidence. A changed worktree causes candidate mismatch at every assessor, Verifier, and approval boundary. Dry runs write only `*-dry-run.*` runtime artifacts; they do not increment attempt or worker sequence, mutate state, or create canonical evidence.

The initial candidate plus two repair rounds are allowed by default. A tentative Implementer attempt is released only for a recognized spawn/exec or agent output-schema startup rejection before business work when the launch worktree fingerprint is unchanged; `worker_run_seq` still increments. All unrecognized failures fail closed and remain charged, including timeouts, ordinary nonzero exits, changed-worktree failures, malformed or missing handoffs, and runtime-integrity failures. Valid blocked Implementer handoffs and Verifier-confirmed repair also consume the business budget. Tester `passed` may proceed. Tester `failed` carries at least one policy-blocking product hypothesis for Verifier classification. Tester `flaky_or_infra` enters `BLOCKED` before Verifier and can retry testing on the same candidate without consuming a repair attempt. Policy-blocking inconclusive evidence blocks for human action and cannot silently approve or consume a repair round.

Use `recover --retry` only from `BLOCKED`. Failed or blocked Correctness Reviewer, Tester, and Security Reviewer workers return to `ASSESSING` on the same candidate and attempt; recovery clears only that role's unaccepted evidence and preserves completed peers. Only deterministic gates or an accepted Verifier decision route product work to `CHANGES_REQUIRED`. Use `recover --ack-human` from `HUMAN_CHECKPOINT`; before clearing identity it kills and drains a recorded worker cgroup, or refuses acknowledgement while an uncontained recorded worker is alive. An approved `--plan-file` may replace Stage scope, increment checkpoint epoch, clear evidence, and bind a new baseline. Use `recover --reopen-review --reason ...` only after Verifier approval and before Slice approval when the operator discovers a new issue.

Runtime cleanup follows no-follow directory descriptors. Process groups, child-subreaper tracking, and optional cgroup v2 reclaim descendants. Completion notifications are unordered wakeups: re-read canonical state and silently discard older Stage, Slice, attempt, role, generation, candidate, session, or epoch notifications.

Context compression is allowed only after the background launch returns, no tool call is outstanding, the checkpoint is durable, output is redirected, and the exact handoff path is known. After compression, reload state, checkpoint, and Current Stage before acting.
