# agent-harness 1.0 execution plan

Status: Complete; approved for local commit, transactional installation, and publication.

## Scope

Redesign the trusted-local engineering Harness as a provider-neutral Stage/Slice workflow with revision-bound evidence, one writable Implementer, independent read-only assessors, a separate Verifier, deterministic gates, bounded repair, and fail-closed approval. Keep project lifecycle adoption separate from the Stage engine and preserve transactional migration from the legacy `codex-harness` installation.

The source repository is authoritative. Installed Skills, plugins, launchers, project configuration, and Hermes configuration are deployment targets only.

## Delivered architecture

- Provider-neutral roles: Orchestrator, Implementer, Correctness Reviewer, Tester, optional Security Reviewer, and Verifier.
- Executable Agent Adapter contract with Codex CLI as a replaceable reference adapter.
- Candidate identity bound to Git base plus a credential-safe worktree fingerprint.
- Canonical state and accepted evidence under Git metadata, with project-facing runtime mirrors.
- Fail-closed handling for stale evidence, protected-path changes, inconclusive or flaky policy-blocking findings, attempt exhaustion, and infrastructure ambiguity.
- Lifecycle-only bootstrap/adoption command surface that generates Stage-compatible state and configuration.
- Transactional installation with exact-object backup identity, post-deploy verification, retained backup archives, atomic rollback quarantine, and no-replace restoration.
- Architecture summary, migration guide, limitations, tests, and the unmodified Deep Research input with a provenance note.

## Key decisions

- The source repository retains the historical `verified-agent-harness` repository name, while the distributed Stage/Slice Skill uses the shorter `agent-harness` identity. The bundled upper-level `project-lifecycle-harness` Skill remains separately named because it classifies, bootstraps, adopts, and activates repositories before routing compatible projects into the Stage/Slice engine.
- Agent adapters are trusted computing-base components responsible for provider sandbox enforcement. The core detects candidate mutation and rejects evidence but does not claim kernel-level containment.
- Deployment requires exclusive writers for target paths. Rollback retains and reports hidden quarantines rather than risking deletion of an unrelated replacement.
- The Deep Research report is design input, not runtime authority. Report recommendations were adapted selectively and are distinguished from implemented architecture and rejected scope in the README.
